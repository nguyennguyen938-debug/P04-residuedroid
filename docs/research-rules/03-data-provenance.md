# R3 — Data and provenance

## R3.1 Raw data is append-only
- Everything under `artifact/results/raw/`, `results/revision-*/`, `results/review-followup-*/` is
  recorded evidence. Never edit, re-sort, deduplicate in place or delete it. Derived files are
  regenerated by scripts; deduplication happens in analysis code with a stated rule (e.g. "render
  keeps the first record").
- Corrections are new files next to the old ones, never in-place edits.

## R3.2 Directory naming
| Pattern | Meaning |
|---|---|
| `raw/<campaign>/<AVD>/` | historical final run |
| `<campaign>-YYYYMMDD/` | dated revision/follow-up cohort |
| `pilot-*` | pilot, excluded from analysis |
| `*_INVALID_<reason>` | discarded run, retained, not analyzed |
| `frozen-<name>/` | pinned source + executables for a run |
| `meta.json`, `meta_start<k>_<sched>.json` | launch metadata; resumes never overwrite `meta.json` |

## R3.3 Minimum files per run directory
`meta.json` (seed, variants, schedules, trials, AVD, ports, toolchain, start time), host action log
(`schedule.jsonl`), device logs (`device_events.jsonl`), receiver/sink logs, failed attempts
(`attempts.jsonl`/`diagnostics.jsonl`), installed APK hashes, and the stage log. Timestamps keep
host and guest clocks in separate fields; never subtract host time from guest time.

## R3.4 Hashes and external inputs
- Third-party binaries (ACRA, Matomo, WorkManager, kotlin-stdlib) are pinned by `deps/SHA256SUMS`.
- External sources (AOSP files, F-Droid index, docs) are stored with `retrieval.json` (URL, time, hash).
- The F-Droid index is a live document; a re-fetch will not match the recorded SHA-256
  (`static/data/index/index-v2.json.sha256`). Treat the recorded hash as the identity of the corpus.

## R3.5 What is not committed
APK cache (5.8 GB), `index-v2.json`, build outputs, private keys, review history (`review/`), private
Figure 1 sources, pre-revision tarballs (see `.gitignore`). If an analysis depends on one of these,
the dependency must be documented and a committed fallback provided (see R5 known issue).

## R3.6 Privacy
Test credentials in `followup/tls-cert/` are public fixture material. Never commit real keys, user
data or anything identifying a real person beyond the paper's author list.
