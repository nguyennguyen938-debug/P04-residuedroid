\begin{abstract}
Android apps persist outboxes and jobs that can outlive a user's withdrawal.
The enforcement problem is not just when to check a toggle: derived data must retain its source policy, and old data must remain distinguishable after consent is granted again.
\sys combines durable source epochs, labels copied with persisted data, and a policy check serialized with each bounded socket write.
We separate collection-only opt-outs, restrictions and deletion contracts, and judge each workload against the contract it states.
A \corpusN-app static screen identifies candidate deferred paths, not runtime violations; of the \promiseApps{} apps with a consent signal, \promisePending{} word their switch as sending or sharing data.
In lifecycle schedules, checks that receive the same metadata show no confirmed disadvantage against the fence.
The fence's advantage is confined to withdrawals that land during an upload: there, a check placed before the request lets the socket accept bytes after the acknowledgement in \raceObsPct{}\% of emulator trials and \racePhoneObsPct{}\% on a phone, and the server still receives the complete request in each such trial; the fence does so in none.
An early check that also closes in-flight sockets before acknowledging matches the fence on this race (\gcloseCloseViol{} of \gcloseN{} trials), but needs a cancellation path to every in-flight request and, in an exploratory count, aborted requests the server had already received.
In a real app, the stock build shares data collected during an opt-out in \airStockViol{} of \airN{} trials; the fenced build has \airFenceViol{} confirmed violations, with \airFenceUnknownV{} trials unknown under the pre-registered oracle.
Label mutants show that a valid but incomplete label bypasses the fence and that a test-time check against traced content catches it.
Already accepted bytes can arrive later, and we make no energy claim.
\end{abstract}
