\begin{abstract}
Android apps persist outboxes and jobs that can outlive a user's withdrawal.
The enforcement problem is not just when to check a toggle: derived data must retain its source policy, and old data must remain distinguishable after consent is granted again.
\sys combines durable source epochs, labels copied with persisted data, and a policy check serialized with each bounded socket write.
We separate collection-only opt-outs, restrictions and deletion contracts, and judge each workload against the contract it states.
A \corpusN-app static screen identifies candidate deferred paths, not runtime violations; of the \promiseApps{} apps with a consent signal, \promisePending{} word their switch as sending or sharing data.
In lifecycle schedules, checks that receive the same metadata had no confirmed violations, like the fence.
The fence differs only when a withdrawal lands during an upload: there, a check placed before the request let the socket accept bytes after the acknowledgement in \raceObsPct{}\% of emulator trials and \racePhoneObsPct{}\% on a phone, and in an exploratory count the server received each such request complete; the fence did so in none.
An early check that also closes in-flight sockets before acknowledging matches the fence at the acknowledgement (\gcloseCloseViol{} of \gcloseN{} trials), but in an exploratory count from the withdrawal's commit it still accepted newly started writes in \gcloseCommitClose{} trials, the fence in none.
In a real app, the stock build shares data collected during an opt-out once the user re-consents, in \airStockViol{} of \airN{} trials; the fenced build has \airFenceViol{} confirmed violations, with \airFenceUnknownV{} trials unknown under the pre-registered oracle.
Label mutants show that a valid but incomplete label bypasses the fence and that a test-time check against traced content catches it.
Already accepted bytes can arrive later, and we make no energy claim.
\end{abstract}
