\paragraph{HTTPS buffering and labels.} A separate Android~15 emulator runs TLS~1.2 over \texttt{SSLEngine} and \texttt{SocketChannel}. Each of eleven conditions has 20 trials. With withdrawal after the first encryption step but before its first socket write, the early-check arm completes 20/20 requests; the fenced arm blocks 20/20 and accepts zero application ciphertext after acknowledgement. The barrier isolates a possible interleaving; it is not a natural-schedule frequency estimate. With a syntactically valid label that deliberately omits the withdrawn source of a derived value, 20/20 requests pass; complete labels block 20/20. Malformed labels also block 20/20. Thus fail-closed validation cannot discover omitted provenance. A mixed-source request is blocked as a whole in 20/20 trials, suppressing its allowed contribution along with the forbidden one.

\paragraph{Cost and residue.} Table~\ref{tab:transport-cost} measures the implemented chunk path, with a matched early-check transport. Cells run in fixed block order on a shared host, so lower measured latency is not evidence that fencing accelerates uploads. Two-process cells include contention for the same policy lock. These CPU observations are not physical energy measurements.

With a stalled TLS receiver and an actual send buffer of 4096 bytes, median ciphertext accepted before withdrawal acknowledgement is 523846 bytes; acknowledgement p95/max is 6.95/12.75\,ms (20 trials).

With a stalled TLS receiver and an actual send buffer of 262144 bytes, median ciphertext accepted before withdrawal acknowledgement is 1022971 bytes; acknowledgement p95/max is 7.21/9.06\,ms (20 trials).

Neither setting accepts application bytes after acknowledgement. Accepted ciphertext can already reside at the peer or in TLS/TCP buffers: it is not a measurement of bytes still unsent by the kernel. The post-acknowledgement kernel snapshots are delayed observations; an exact unsent-at-ack count remains unmeasured. Shrinking the send buffer reduces observed accepted exposure in this schedule, but cannot guarantee recall.
